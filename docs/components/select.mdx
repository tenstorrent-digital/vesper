# Select

A form-ready dropdown select component supporting controlled and uncontrolled usage. It shares the same sizes, variants, labels, and messages as [the `TextInput` component](./text-input.mdx), and portals its dropdown automatically so it works inside dialogs.

<Select
  aria-label="Fruit"
  placeholder="Select a fruit"
  options={[
    { value: "apple", label: "Apple" },
    { value: "banana", label: "Banana" },
    { value: "cherry", label: "Cherry" },
  ]}
/>

## Options

| Prop            | Type                                                                                | Description                                                                                                                        | Default              |
| --------------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| `options`       | `(SelectItem \| string)[]`                                                          | The list of selectable options displayed in the dropdown. Strings are treated as both the label and the value.                     | —                    |
| `size`          | `"sm" \| "md" \| "lg"`                                                              | The size of the select trigger. Affects height, padding, and typography.                                                           | `"md"`               |
| `variant`       | `"default" \| "warning" \| "success" \| "error"`                                    | The visual variant, which determines color scheme and message icon.                                                                | `"default"`          |
| `label`         | `string`                                                                            | An optional label displayed above the trigger, and used as its accessible name. An asterisk is appended when `required` is `true`. | —                    |
| `message`       | `string`                                                                            | An optional message displayed below the trigger, paired with a variant-specific icon.                                              | —                    |
| `placeholder`   | `string`                                                                            | Placeholder text shown in the trigger when no value is selected.                                                                   | `"Select an option"` |
| `icon`          | `ReactNode`                                                                         | An optional icon rendered at the leading edge of the trigger.                                                                      | —                    |
| `value`         | `string \| null`                                                                    | The currently selected value (controlled mode). Pass `null` to represent no selection.                                             | —                    |
| `defaultValue`  | `string \| null`                                                                    | The initial selected value (uncontrolled mode).                                                                                    | —                    |
| `onValueChange` | `(value: string \| null) => void`                                                   | Callback invoked with the new value whenever the selection changes, or `null` when it is cleared.                                  | —                    |
| `name`          | `string`                                                                            | The form field name submitted with form data.                                                                                      | —                    |
| `form`          | `string`                                                                            | Associates the select with a `<form>` element by its `id`.                                                                         | —                    |
| `id`            | `string`                                                                            | An identifier applied to the trigger, used to reference it from form validation errors.                                            | —                    |
| `required`      | `boolean`                                                                           | When `true`, marks the select as required for native form validation.                                                              | `false`              |
| `disabled`      | `boolean`                                                                           | When `true`, prevents interaction with the trigger and dropdown.                                                                   | `false`              |
| `container`     | `HTMLElement \| ShadowRoot \| null \| RefObject<HTMLElement \| ShadowRoot \| null>` | Specify the element or shadow root to portal the dropdown into.                                                                    | —                    |

`aria-label`, `aria-labelledby`, `aria-describedby`, and `aria-invalid` are all forwarded to the select trigger. Any other props are forwarded to the wrapping `<div>` element.

### `SelectItem` options

| Property | Type     | Description                                                                                  |
| -------- | -------- | -------------------------------------------------------------------------------------------- |
| `label`  | `string` | The text displayed for this option in the dropdown, and in the trigger once it is selected.  |
| `value`  | `string` | The underlying value submitted with form data and passed to `onValueChange`. Must be unique. |

A plain string option is shorthand for a `SelectItem` whose `label` and `value` are both that string.

If your list is long enough that users will want to search it, reach for [the `Combobox` component](./combobox.mdx) instead: it renders the same trigger sizes and variants, but filters its options as the user types.

## Examples

### Defining options

Each entry in the `options` array can either be a `SelectItem`, or a plain string. Use `SelectItem` objects when the value associated with each item differs from the text you want to display:

<Select
  label="Region"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  label="Region"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>;
```

When the displayed text is the same as the value of the item, a string option is a convenient shorthand:

<Select
  label="Country"
  placeholder="Select a country"
  options={["Canada", "Japan", "Norway"]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  label="Country"
  placeholder="Select a country"
  options={["Canada", "Japan", "Norway"]}
/>;
```

Both shapes can be mixed in the same `options` array. Options are rendered in the order they are provided, and the selected one is marked with a checkmark when the dropdown is open.

### Uncontrolled vs controlled

The simplest way to use the `Select` component is to render it in an uncontrolled fashion, where the component keeps track of its own selection. Pass `defaultValue` if you need an option to be selected initially:

<Select
  label="Region"
  defaultValue="eu"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  label="Region"
  defaultValue="eu"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>;
```

If you need to control which option is selected, use the `value` and `onValueChange` props. `value` is the `value` of the selected option, and is `null` when nothing is selected. There is no built-in way for a user to clear a selection, so pass `null` when you need to return the select to its placeholder state:

<SelectDemo kind="controlled" />

```tsx
import { useState } from "react"
import { Select } from "@tenstorrent/vesper/select"
import { Button } from "@tenstorrent/vesper/button"

const [fruit, setFruit] = useState<string | null>("apple")

<Select
  label="Fruit"
  placeholder="Select a fruit"
  value={fruit}
  onValueChange={setFruit}
  options={[
    { label: "Apple", value: "apple" },
    { label: "Banana", value: "banana" },
    { label: "Cherry", value: "cherry" },
  ]}
/>

// clearing the selection shows the placeholder again
<Button onClick={() => setFruit(null)}>Reset</Button>
```

### Different sizes

The `Select` component can be rendered at `sm`, `md`, or `lg` size, defaulting to `md`. Size affects the height, padding, and text styles of the trigger, as well as the size of its icons.

<Select
  size="sm"
  aria-label="Country"
  placeholder="A small select"
  options={[
    { label: "Canada", value: "ca" },
    { label: "Japan", value: "jp" },
    { label: "Norway", value: "no" },
  ]}
/>
<Select
  size="md"
  aria-label="Country"
  placeholder="A medium select"
  options={[
    { label: "Canada", value: "ca" },
    { label: "Japan", value: "jp" },
    { label: "Norway", value: "no" },
  ]}
/>
<Select
  size="lg"
  aria-label="Country"
  placeholder="A large select"
  options={[
    { label: "Canada", value: "ca" },
    { label: "Japan", value: "jp" },
    { label: "Norway", value: "no" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select"

const options = [
  { label: "Canada", value: "ca" },
  { label: "Japan", value: "jp" },
  { label: "Norway", value: "no" },
]

<Select size="sm" aria-label="Country" placeholder="A small select" options={options} />
<Select size="md" aria-label="Country" placeholder="A medium select" options={options} />
<Select size="lg" aria-label="Country" placeholder="A large select" options={options} />
```

### Rendering an icon

You can render an icon at the leading edge of the trigger via the `icon` prop. The icon is decorative, and stays in place as the selection changes:

<Select
  label="Region"
  icon={<Globe />}
  placeholder="Select a region"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Globe } from "@tenstorrent/vesper/icons";
import { Select } from "@tenstorrent/vesper/select";

<Select
  label="Region"
  icon={<Globe />}
  placeholder="Select a region"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>;
```

> [!NOTE]
>
> The trailing caret is rendered by the component itself, and flips between its open and closed states as the dropdown is toggled. Only the leading icon is configurable.

### Message

You can render an additional line of text under the trigger via the `message` prop. Combine it with the `variant` prop to indicate the tone of the message to the user.

<Select
  label="Region"
  placeholder="Select a region"
  message="Only regions available on your plan are listed."
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  label="Region"
  placeholder="Select a region"
  message="Only regions available on your plan are listed."
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>;
```

The message is linked to the trigger via `aria-describedby`, so it is announced along with the field by assistive technology.

### Variants

The `Select` component can be rendered in one of four variants: `default`, `warning`, `success`, or `error`. The variant determines the colour scheme of the trigger, as well as the icon paired with its `message`.

#### Default variant

A `Select` renders with the `default` variant when no `variant` prop is specified. Its `message` is best suited for neutral hints:

<Select
  label="Region"
  placeholder="Select a region"
  message="You can change this later in your settings."
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  label="Region"
  placeholder="Select a region"
  message="You can change this later in your settings."
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>;
```

#### Warning variant

Use the `warning` variant to flag a selection that needs attention, but that doesn't prevent the form from being submitted:

<Select
  variant="warning"
  label="Region"
  defaultValue="ap"
  message="This region has limited availability."
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  variant="warning"
  label="Region"
  defaultValue="ap"
  message="This region has limited availability."
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
```

#### Success variant

The `success` variant is best suited for confirming that a selection has been validated as expected:

<Select

    { label: "United States", value: "us" },

  ]}
/>

```tsx

  variant="success"
  label="Region"
```

The `error` variant highlights a missing or invalid selection that must be corrected before the form can be submitted:

    { label: "United States", value: "us" },

    { label: "Asia Pacific", value: "ap" },
  ]}
/>


### Labels and required fields

> [!IMPORTANT]
>
> Always give a `Select` an accessible name by passing a `label`, an `aria-label`, or an `aria-labelledby` that points at existing visible text. A `Select` with none of these is announced with no indication of what it is for.

When a `label` is provided, it is rendered above the trigger and associated with it via the trigger's `id`. It becomes the trigger's accessible name, and clicking it opens the dropdown:

<Select
  required
  label="Region"
  placeholder="Select a region"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

// Visible label — preferred
<Select
  required
  label="Region"
  placeholder="Select a region"
  options={REGIONS}
/>;

// No visible label — provide an `aria-label` instead
<Select
  required
  aria-label="Region"
  placeholder="Select a region"
  options={REGIONS}
/>;
```

Passing `required` marks the field as required for native form validation, and appends an asterisk to the `label`. When rendering without a visible `label`, nothing marks the field as required on screen, so mention it in the `message` if users need to know before submitting.

An `id` is generated for the trigger for you, but you can provide your own via the `id` prop if you need to reference the field elsewhere. Any `aria-describedby` you pass is merged with the automatically generated `message` id, so both remain announced by assistive technology.

### Disabling the select

Pass `disabled` to prevent all interaction with the trigger and its dropdown. A disabled `Select` still displays its current selection, but is skipped in the tab order and excluded from form data:

<Select
  disabled
  label="Region"
  defaultValue="eu"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>

```tsx
import { Select } from "@tenstorrent/vesper/select";

<Select
  disabled
  label="Region"
  defaultValue="eu"
  options={[
    { label: "United States", value: "us" },
    { label: "Europe", value: "eu" },
    { label: "Asia Pacific", value: "ap" },
  ]}
/>;
```

### Usage in forms

`Select` renders a hidden form control alongside its trigger, so passing a `name` includes the selected value in form submissions, and `required` participates in native form validation. Use the `form` prop to associate the field with a `<form>` rendered elsewhere on the page:

<SelectDemo kind="form" />

```tsx
import { Button } from "@tenstorrent/vesper/button";
import { Select } from "@tenstorrent/vesper/select";

<form action="/api/preferences" method="post">
  <Select
    required
    name="fruit"
    label="Fruit"
    placeholder="Select a fruit"
    options={[
      { label: "Apple", value: "apple" },
      { label: "Banana", value: "banana" },
      { label: "Cherry", value: "cherry" },
    ]}
  />
  <Button type="submit">Submit</Button>
</form>;
```

The value submitted is the `value` of the selected option, not the `label` displayed in the trigger — the form above submits `fruit=apple` when "Apple" is selected.
